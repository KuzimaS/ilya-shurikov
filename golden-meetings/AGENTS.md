# Обновление конкурса менеджеров

Правило пользователя от 09.09.2026: не засчитывать повторно одного клиента.

- Один ID лида CRM учитывается один раз в назначениях и отдельно один раз в проведениях за весь конкурс, независимо от сотрудника, даты и ID встречи.
- При нескольких записях сохранять самое раннее создание назначения или самое раннее начало проведения. Повторное назначение и перенос не дают дополнительного зачёта.
- Прямые решения пользователя о принадлежности встречи имеют приоритет над временем начала. Они хранятся в `attribution-overrides.json` и применяются импортом до удаления дублей. Решение от 10.09.2026: очную встречу за 09.09 снять с Файбушевича Евгения и зачесть Митроченкову Андрею. Не возвращать её Файбушевичу при повторной выгрузке; общий зачёт клиента остаётся один.
- Участники адаптации не входят в конкурс менеджеров. Сначала применять актуальный состав, затем убирать повторы.
- Импортировать полные атомы выгрузок по датам через `scripts/import-records.cjs`. Входной формат описан в начале скрипта. Перед импортом сверить исходные атомы с агрегатами выгрузки и проверить полноту дат.
- Для новой даты без атомов явно подтвердить нулевой результат по исходной выгрузке. Не считать отсутствие строки доказательством нуля.
- Публиковать `assignedEvents` и `heldEvents` с `clientKey`; назначения рассчитывать через `Contest.assignedCounts`. Не обновлять только числовой календарь и не использовать старые скрипты, теряющие журналы.
- В публичных данных хранить только SHA-256 отпечатки ID, дату и сотрудника. Исходные выгрузки, ID лидов и ссылки CRM не коммитить.
- Перед публикацией выполнить `Contest.validateForPublish` и `node checks.cjs`. Повторный импорт той же выгрузки не должен менять результат.
- При обновлении GitHub брать свежую ветку и сохранять изменения остальных разделов сайта.
