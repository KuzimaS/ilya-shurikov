# Спринт встреч: 7–30 сентября 2026

Участники и премии находятся в `contest-data.js`, проверка данных и расчёты в `contest-core.js`.

## Обновление результатов

1. Включите ввод. Для назначений нажмите день сотрудника в календаре, для проведённых откройте журнал. Укажите дату создания назначения или дату проведения и пары «ID встречи; ID лида», по одной на строку. Один клиент за конкурс засчитывается один раз в каждой категории независимо от сотрудника.
2. Локальные изменения сохраняются как черновик. Они не передаются телевизорам до публикации. Кнопка «Резервная копия» сохраняет полный проверенный набор. Импорт показывает предварительные итоги; доступна отмена последнего изменения.
3. Нажмите «Опубликовать для ТВ», скачайте `state.json`, загрузите его в эту папку в ветке `gh-pages` на GitHub и сохраните коммит. Можно передать выгрузку ассистенту для публикации. Не загружайте исходные выгрузки клиентов и персональные контакты.
4. После обновления GitHub Pages ТВ-панели считывают опубликованный `state.json` каждые 30 секунд. Они не используют локальный черновик технички. При отсутствии сети остаётся последняя проверенная опубликованная версия и видимое сообщение.

GitHub Pages не принимает запись из анонимного браузера. Публикация выполняется через GitHub с правами владельца репозитория. Секретов и токенов в коде нет. До публикации согласуйте изменения, если другой оператор уже обновил общий файл: система предупреждает о различии версий.

Журнал публикует отпечаток ID, дату и сотрудника, без исходного ID или сведений о клиенте. Повтор ID встречи или клиента в одной категории за весь конкурс блокируется. При исправлении даты уберите неверную запись и внесите правильную. Старые общие счётчики сохраняются как непроверенные, входят в локальные итоги и требуют привязки к датам до публикации.

## Премии и места

Назначения: первые три за день без оплаты; начиная с четвёртой +1 000 ₽ за каждую. Сумма бонусов по всем датам конкурса.

Проведённые: 3 / 5 / 7 / 9 / 12 / 15 встреч дают итоговую награду 10 / 20 / 35 / 45 / 60 / 70 тыс. ₽ соответственно. Ступени не складываются. Если премия уже частично выплачена, к выплате остаётся разница; текущий сайт показывает начисления, не фактические выплаты.

При равных результатах одинаковое место: 1, 1, 3. Нулевой результат без места и медали. В топ-10 показаны десять сотрудников; внутри равенства действует стабильный порядок списка, одинаковое место сохраняется. Рейтинг отделов по общему количеству встреч, без корректировки на размер отдела и без условий по конверсии.

ТВ одного отдела размещает всех его сотрудников на одном экране; календарь назначенных переключает недели. Режим «Топ отделов» показывает только место, отдел и общее число встреч.

## Проверка

`node golden-meetings/checks.cjs` проверяет суммы на границах ступеней, распределение премий, даты, дубли, импорт, сохранение старых счётчиков, равные места и синтаксис страниц.

## Защита от повторного зачёта

Один ID лида CRM засчитывается только один раз в назначениях и отдельно один раз в проведениях за весь конкурс. Перенос времени, другая дата, другой сотрудник или новый ID встречи не дают повторного зачёта. При импорте сохраняется самая ранняя запись по времени создания назначения или начала проведения. Проверка ведётся по ID лида; один человек в разных лидах требует объединения в CRM.

Назначения хранятся в `assignedEvents`, проведения в `heldEvents`. Поле `clientKey` содержит SHA-256 от `contestId + ":client:" + ID лида`. Календарь рассчитывается из журнала. Импорт и публикация агрегатов без журналов клиентов запрещены. Старые черновики можно сохранить резервной копией, затем загрузить текущую опубликованную версию.

Для обновления из полной выгрузки атомов: `node scripts/import-records.cjs source-records.json state.json`. Формат входа и требования к полноте указаны в скрипте и AGENTS.md. Исходные клиентские данные не загружать в GitHub.
