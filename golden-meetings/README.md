# Спринт встреч: 7–30 сентября 2026

Участники и премии находятся в `contest-data.js`, проверка данных и расчёты в `contest-core.js`.

## Обновление результатов

Публичная техпанель работает только для просмотра. В ней нет ввода встреч, импорта, изменения выплат или публикации. Старые локальные черновики не читаются. Поиск, фильтры, календарь и журналы встреч доступны всем посетителям.

Илья Шуриков передаёт выгрузки и подтверждения выплат ассистенту. Ассистент проверяет полные журналы, исключает дубли, сохраняет ручные решения и оплаты, затем публикует изменения через GitHub. Не изменять статусы выплат без подтверждения пользователя.

Запись в общие данные защищена правами GitHub на репозиторий. У публичного сайта нет API записи, пароля в JavaScript или токена доступа. Пользователи с правами записи в репозиторий по-прежнему могут публиковать изменения через GitHub; режим просмотра не меняет эти права.

Все панели считывают опубликованный `state.json` каждые 30 секунд. При отсутствии сети показывается последняя сохранённая опубликованная версия и сообщение об ошибке. Сохранённые черновики браузера на результаты не влияют.

Журнал содержит отпечатки ID, дату и сотрудника. Исходные выгрузки клиентов, контакты и ID лидов в GitHub не публикуются.

## Премии и места

Назначения: первые три за день без оплаты; начиная с четвёртой +1 000 ₽ за каждую. Сумма бонусов по всем датам конкурса.

Проведённые: 3 / 5 / 7 / 9 / 12 / 15 встреч дают итоговую награду 10 / 20 / 35 / 45 / 60 / 70 тыс. ₽ соответственно. Ступени не складываются. Если премия уже частично выплачена, к выплате остаётся разница; во вкладке «Выплаты» показаны начисления, подтверждённые оплаты и остаток.

При равных результатах одинаковое место: 1, 1, 3. Нулевой результат без места и медали. В топ-10 показаны десять сотрудников; внутри равенства действует стабильный порядок списка, одинаковое место сохраняется. Рейтинг отделов по общему количеству встреч, без корректировки на размер отдела и без условий по конверсии.

ТВ одного отдела размещает всех его сотрудников на одном экране; календарь назначенных переключает недели. Режим «Топ отделов» показывает только место, отдел и общее число встреч.

## Проверка

`node golden-meetings/checks.cjs` проверяет суммы на границах ступеней, распределение премий, даты, дубли, импорт, сохранение старых счётчиков, равные места и синтаксис страниц.

## Защита от повторного зачёта

Один ID лида CRM засчитывается только один раз в назначениях и отдельно один раз в проведениях за весь конкурс. Перенос времени, другая дата, другой сотрудник или новый ID встречи не дают повторного зачёта. При импорте сохраняется самая ранняя запись по времени создания назначения или начала проведения. Проверка ведётся по ID лида; один человек в разных лидах требует объединения в CRM.

Назначения хранятся в `assignedEvents`, проведения в `heldEvents`. Поле `clientKey` содержит SHA-256 от `contestId + ":client:" + ID лида`. Календарь рассчитывается из журнала. Импорт и публикация агрегатов без журналов клиентов запрещены. Старые черновики браузера больше не используются.

Для обновления из полной выгрузки атомов: `node scripts/import-records.cjs source-records.json state.json`. Формат входа и требования к полноте указаны в скрипте и AGENTS.md. Исходные клиентские данные не загружать в GitHub.
